# 米家设备支持矩阵

更新时间：`2026-07-24`

本页记录插件内置画像及其安全边界。设备能力会受地区、固件、账号权限和米家云端规格影响；“已内置”不等于所有设备批次均已实测。

## 适配层级

- **型号精确画像**：`model` 命中 `MODEL_PROFILES`。插件使用该型号专属的属性、状态和动作清单。
- **类别画像**：未命中精确型号时，按管理员配置的 `device_category_map` 提供中文展示和管理员命令参考。
- **动态能力检查**：从云端观察原始属性与动作，仅用于诊断和提交适配资料。

LLM 设备控制采用更严格的边界：

- 设备必须在 `control_tool.allowed_devices` 白名单中；
- `control_tool` 默认关闭，`admin_only` 默认开启；
- 只有命中受信任的**型号精确画像**，并且画像存在可写属性或动作时，才会开放 LLM 直接控制；
- 未知型号即使能探测到属性或配置了类别，也只允许检查；可写白名单仅来自精确型号画像；
- 红外设备不开放 LLM 直接控制，建议使用米家场景。

## 类别画像

下列类别用于中文展示、状态读取和管理员命令参考。它们不是对所有同类设备的兼容承诺；未知型号的 LLM 直接控制权限仍以精确型号画像为准。

| 类别 | 覆盖方向 | 已知边界 |
| --- | --- | --- |
| 空调类别 | 电源、温度、模式、风速、扫风 | 不同空调伴侣和红外规格差异较大 |
| 净化器类别 | 电源、模式、风速、空气质量 | 属性名和模式值可能因代际不同 |
| 风扇类别 | 电源、风速、自然风、摇头 | 部分角度和模式值需要型号适配 |
| 蒸煮锅类别 | 温度、时长、模式、保温 | 烹饪模式和范围因型号不同 |
| 空气炸锅类别 | 温度、时长、模式、保温 | 烹饪程序和范围因型号不同 |
| 温湿度计类别 | 温湿度、电量等状态 | 多数设备只读，休眠时可能无数据 |
| 体脂秤类别 | 体重、体脂和测量状态 | 测量时才可能返回完整数据 |
| 扫地机类别 | 清扫参数、耗材状态和常用动作 | 地图、房间和清扫动作差异明显 |
| 热水器类别 | 温度、保温和模式 | 水壶、热水器规格不可混用 |
| 路由器类别 | 速率、连接数、联网与 Wi-Fi 状态 | 云端通常只提供有限状态 |
| 音箱类别 | 音量、静音、播放状态和媒体动作 | 带参动作必须按精确型号验证 |
| 开关类别 | 电源、模式等基础能力 | 多路开关需要型号级通道映射 |
| 门磁传感器类别 | 接触、照度、电量等状态 | 通常只读 |
| 燃气传感器类别 | 报警、浓度等状态 | 通常只读；不能替代安全报警设备 |

## 如何确认设备是否可用

1. 在“米家管理”中同步设备，并为目标设备设置别名。
2. 使用 `/米家详情 [别名]` 查看状态，使用 `/米家帮助 [别名]` 查看管理员命令参考。
3. 如需 LLM 控制，仅将低风险设备加入 `allowed_devices`。
4. 调用 `list_mihome_devices`；只有 `direct_control_supported: true` 的设备才可继续。
5. 调用 `inspect_mihome_device`，控制时只使用返回的 `writable_properties` 和 `actions`。`observed_capabilities` 只供诊断。

`control_mihome_device` 单批最多 5 项并按顺序执行，已完成项保留结果。应逐项核对返回结果，不要将“部分成功”理解为整批完成。

## 申请适配

请使用“设备适配申请”Issue 模板，并提供：

- 设备品牌、名称和准确 `model`；
- AstrBot、插件和 `mijiaAPI` 版本；
- 可复现的操作、期望结果和实际结果；
- 人工检查并脱敏后的设备规格 JSON。

禁止提交 Token、Cookie、认证文件、账号信息、家庭信息或 DID。规格 JSON 中如含设备标识或账号数据，也必须先删除或替换。
