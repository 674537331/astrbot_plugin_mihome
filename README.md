# AstrBot 米家控制

通过米家云端在 AstrBot 中管理、查询和控制智能家居设备。v8 提供 AstrBot 内置的“米家管理”页面，并为只读查询、场景执行和设备控制分别设置权限边界。

> 本插件会操作真实家居设备。首次使用前请阅读[安全与隐私](#安全与隐私)，设备控制和场景 Tool 建议始终仅向 AstrBot 管理员开放。

## 功能概览

- 在 AstrBot 插件详情页内扫码登录，无需另开 Web 服务。
- 同步米家设备，编辑设备别名与类别映射，查看只读实时状态。
- 查看、同步场景缓存，检查账号、网络、缓存与映射状态。
- 使用管理员聊天命令查询设备、控制设备和执行米家场景。
- 可选的只读、场景和设备控制 LLM Tool，默认按最小权限配置。
- 内置常用设备的中文属性、状态和动作画像，详见[设备支持矩阵](docs/device_support_matrix.md)。

“米家管理”WebUI 是配置与诊断页面，**不提供设备遥控按钮、设备控制接口或场景执行接口**。真实操作只能通过管理员命令，或管理员明确启用且通过权限检查的 LLM Tool 发起。

## 环境要求与安装

- AstrBot `>= 4.24.2`（内置 Plugin Pages 页面所需）
- Python `>= 3.10, < 4.0`（同时须满足当前 AstrBot 运行要求）
- `mijiaAPI==4.1.3`
- `qrcode==8.2`

推荐在 AstrBot 插件市场中安装或更新，AstrBot 会按 `requirements.txt` 安装依赖。手动部署时，将插件目录放入 AstrBot 插件目录，并在 AstrBot 使用的 Python 环境中执行：

```bash
python -m pip install -r requirements.txt
```

更新插件后，请在 AstrBot WebUI 中重载插件；若依赖未被正确替换，请重启 AstrBot 后再检查。

## 快速开始

1. 在 AstrBot WebUI 中打开“插件”→“米家控制”→“米家管理”。
2. 在“概览”中扫码登录，并等待授权完成。
3. 进入“设备管理”，同步云端设备。
4. 为需要使用的设备设置唯一、清楚的别名，例如“客厅空调”，并选择正确类别。
5. 保存映射后，在设备详情中检查只读状态。
6. 如需自然语言调用，再按用途分别启用只读、场景或设备控制 Tool。

为避免二维码票据进入群聊或平台消息日志，登录必须在内置“米家管理”页面完成；登录后可以继续使用聊天命令同步和查询：

```text
/刷新米家
/米家详情 客厅空调
/米家帮助 客厅空调
```

`device_map` 的值是设备 DID，不是型号 `model`。普通用户建议在“米家管理”中可视化编辑；AstrBot 原生配置页中的 JSON 字段仅作为批量编辑和兼容入口。

## 聊天命令

除 `/米家帮助` 外，下列命令均要求 AstrBot 管理员权限。

| 命令 | 作用 |
| --- | --- |
| `/米家帮助`、`/mihome_help` | 查看命令总览 |
| `/米家帮助 [设备别名]` | 查看设备可用属性、动作和示例 |
| `/米家登录` | 安全提示并引导至内置“米家管理”页面授权，不在聊天中发送登录链接 |
| `/米家状态` | 查看登录、共享设备、场景缓存和最近控制状态 |
| `/米家登出` | 清除本地凭证与状态 |
| `/刷新米家` | 同步设备并刷新 DID、model 缓存 |
| `/米家详情 [设备别名]` | 查看能力与实时状态 |
| `/米家控制 [设备别名] [开/关]` | 设置电源状态 |
| `/米家控制 [设备别名] [属性] [值]` | 设置设备属性 |
| `/米家控制 [设备别名] [动作]` | 执行设备动作 |
| `/米家场景列表` | 同步并列出云端场景 |
| `/米家场景 [场景名或 scene_id]` | 执行指定场景 |

示例：

```text
/米家控制 客厅空调 开
/米家控制 客厅空调 温度 26
/米家控制 扫地机 开始清扫
/米家场景 晚安模式
```

请优先参考 `/米家帮助 [设备别名]` 返回的能力和示例。新型号或云端规格存在差异时，命令不保证兼容；涉及多个设备的操作优先使用米家 App 中预先配置的“手动执行”场景。

## LLM Tool 与权限

三组 Tool 相互独立，可在“米家管理”或 AstrBot 原生配置页中开启。

### 只读 Tool

配置项 `enable_readonly_tool`，默认关闭：

- `list_configured_mihome_aliases`：列出 `device_map` 中已配置的别名。
- `read_mihome_device_status_by_alias`：按精确别名实时读取设备状态。

它们不能控制设备、执行动作或运行场景。

### 场景 Tool

配置组 `scene_tool`，`enable` 默认关闭，`admin_only` 默认开启：

- `list_cached_mihome_scenes`：只读查看已同步的场景缓存。
- `execute_mihome_scene`：执行明确匹配的场景。

使用前先通过 `/米家场景列表` 或管理页面同步缓存。场景可能同时控制多台真实设备，建议保留 `admin_only: true`，并使用清晰且不重复的场景名。

### 设备控制 Tool

配置组 `control_tool`，提供四个工具：

- `list_mihome_devices`：列出控制白名单中的设备与静态能力概览。
- `inspect_mihome_device`：检查一台白名单设备的静态可控能力和云端观测能力。
- `control_mihome_device`：顺序设置一个或多个静态画像允许的属性。
- `call_mihome_action`：执行静态画像明确允许的动作。

安全默认值：

```yaml
control_tool:
  enable: false
  admin_only: true
  allowed_devices: []
```

- 总开关默认关闭。
- `admin_only` 只信任 AstrBot 管理员判定，不会自动把群主或群管理员视为 AstrBot 管理员。
- `allowed_devices` 只接受 `device_map` 中的精确别名；空列表会失败关闭，即使开启总开关也不能控制任何设备。
- 设备必须命中受信任的型号精确画像。显式类别画像和动态能力可以帮助检查与适配，但不会自动扩大控制范围，也不能据此直接由 LLM 控制未知型号。
- `control_mihome_device` 单批最多 5 项，按顺序执行，**不是原子操作**；部分成功时不会回滚已经完成的项目。
- 同一插件实例同时只执行一个设备控制任务；已有任务运行时，并发请求会被拒绝。对同一设备完成一次属性控制或动作后，至少等待 3 秒才能再次操作。
- 带参数动作只对经过精确型号验证的能力开放，不会把任意参数直接透传给云端。
- 云端返回 `code=1` 时只表示网关已接收请求，Tool 会标记为 `unconfirmed`，不会据此声称真实设备已经执行成功。

建议先加入一台低风险设备，使用 `list_mihome_devices` 和 `inspect_mihome_device` 核对能力，再逐步扩大白名单。

## 设备适配

插件按以下顺序解析设备画像：

1. 精确型号画像；
2. 管理员配置的类别画像；
3. 动态能力检查。

动态能力检查是诊断信息，不是可信控制清单。未知型号不会开放 LLM 直接控制；可以提交脱敏后的规格申请适配，或改用已经在米家 App 中验证过的场景。

当前画像、实测状态和已知边界见[设备支持矩阵](docs/device_support_matrix.md)。矩阵中的“已适配”表示插件包含相应映射，不等于所有固件、地区和设备批次均已实测。

## 从 v7 升级到 v8

v8 会继续读取原有 `device_map`、`device_category_map`、`scene_tool` 和只读 Tool 配置，无需重新登录或重新绑定设备。升级后请完成以下检查：

1. 将 AstrBot 升级到 `4.24.2` 或更高版本。
2. 确认依赖已更新到 `mijiaAPI==4.1.3`。
3. 打开“米家管理”，同步设备并检查别名、类别和场景缓存。
4. 新增的 `control_tool` 默认关闭；确需使用时，保持 `admin_only` 开启并逐项选择 `allowed_devices`。
5. 先检查设备能力，再进行低风险测试。未知型号请使用场景或提交适配，不要把动态探测结果当作可写白名单。
6. `/米家登录` 从 v8 起只提供安全引导；需要重新授权时请在内置“米家管理”页面扫码。

若升级后管理页面没有显示，请确认 AstrBot 版本并重载插件；若旧配置由手工 JSON 维护，请先备份再通过管理页面保存一次。

## 安全与隐私

- 米家认证文件保存在 AstrBot 数据目录下的 `plugin_data/astrbot_plugin_mihome/auth.json`。
- 设备、场景和诊断状态保存在同目录的 `state.json`。
- WebUI 只显示凭证是否存在，不返回或下载 Cookie、Token、认证文件内容。
- 扫码链接只在插件进程内存中短暂保存，并由本地生成二维码；完成、超时或退出后会清理，也不会通过聊天命令发送。
- 设备控制 Tool 的结果不向模型返回 DID，日志不会记录带参动作的文本内容。
- 分享日志或提交 Issue 前，必须删除 Token、Cookie、认证数据、账号信息、家庭信息和 DID。

请不要将 AstrBot WebUI 暴露到不受信任的公网环境。账号登出会清除本地凭证与状态；需要备份时请保护备份文件，避免上传到公开仓库或网盘公开链接。

## 常见问题

### 看不到“米家管理”

确认 AstrBot `>= 4.24.2`，更新后重载插件或重启 AstrBot。Plugin Pages 入口位于插件详情页。

### 扫码后仍未登录

检查 AstrBot 所在主机能否访问米家云端，确认使用正确地区的米家账号，并查看 `/米家状态` 与 AstrBot 日志。不要把认证文件或完整登录响应粘贴到 Issue。

### 同步不到设备或共享设备

先在米家 App 中确认设备可见、在线且账号地区一致，再执行 `/刷新米家`。共享设备能力受米家云端权限限制，部分设备可能无法读取或控制。

### 设备有状态但不能由 LLM 控制

依次确认：

1. `control_tool.enable` 已开启；
2. 当前调用者是 AstrBot 管理员（当 `admin_only` 开启时）；
3. 设备精确别名已加入 `allowed_devices`；
4. 设备命中可信的型号精确画像；
5. `inspect_mihome_device` 将目标列在 `writable_properties` 或 `actions` 中。

动态能力中出现某个属性，不表示该属性已获准写入。

### 一批操作部分成功

设备属性按顺序下发且不回滚。请根据 Tool 返回的每项结果确认真实状态，再单独重试失败项；不要在结果返回前假设全部成功。`unconfirmed` 表示网关接收了请求但云端没有确认设备执行结果，应以设备实时状态为准。

### 场景名称匹配失败

重新执行 `/米家场景列表` 同步缓存。存在同名场景时使用 `scene_id`；建议在米家 App 中使用唯一、明确的场景名。

安装依赖后，可运行：

```bash
python -m compileall -q .
python -m unittest discover -s tests -v
ruff check .
```

提交设备适配时，请使用 Issue 模板，仅提供设备 `model` 和经过检查、脱敏的规格 JSON。禁止提交 DID、Token、Cookie、认证文件或其他账号信息。
