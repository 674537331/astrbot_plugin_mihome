# 🌟 AstrBot MiHome Control

基于 [AstrBot](https://github.com/Soulter/AstrBot) 框架开发的支持自然语言调用的米家智能家居云端控制插件。

## ✨ 核心特性

* 🏠 **内置米家管理**：在 AstrBot 插件详情页中完成扫码登录、设备同步、别名与类别映射、场景缓存查看和运行诊断。
* 🔒 **扫码登录**：认证凭证安全保存在 `plugin_data` 目录中，便于备份、迁移与卸载清理。
* 🚀 **场景调用**：直接通过米家APP内已有场景对多个设备进行复杂调整，支持指令和LLM工具自然语言调用！
* 🧠 **设备画像**：将用户别名、中文控制词与底层属性键解耦。
* 📊 **中文状态**：基于本地画像与云端返回结果，对设备状态项进行中文翻译与单位美化展示。
* 🔑 **设备兼容**：对所有设备均已适配直接开关，并支持通过原始属性（如 `temperature 26`）进行透传控制。

## 🛠️ 安装依赖

内置“米家管理”页面使用 AstrBot Plugin Pages，需要 **AstrBot >= 4.24.2**。版本较低时请先升级 AstrBot，否则插件详情页不会显示管理页面。

请确保在 AstrBot 的 Python 环境中安装了以下依赖：

```bash
pip install -r requirements.txt
```

## 📖 使用指南

发送 `/米家帮助`（英文别名：`/mihome_help`）可随时查看完整指令总览；发送 `/米家帮助 [设备别名]` 可查看设备专属控制示例。

如果同时安装了 [astrbot_plugin_help](https://github.com/Kylerupinski/astrbot_plugin_help)，公开的 `/米家帮助` 会自动显示在 `/helps` 菜单中。该帮助插件默认隐藏管理员命令；如需在 `/helps` 中展开显示本插件的其他命令，请在其配置中开启 `show_all_cmds`。

<details>
<summary><b>🚀 快速上手：使用“米家管理”完成首次配置（点击展开）</b></summary>

对于初次使用的用户，推荐直接使用 AstrBot 内置管理页面：

### 步骤 1：打开“米家管理”

进入 AstrBot WebUI 的插件列表，打开本插件的详情页，然后点击 **米家管理**。

### 步骤 2：扫码授权登录

在“概览”中点击 **扫码登录**，使用米家 App 扫描二维码并确认授权。授权成功后，页面会显示当前账号状态。

也可以继续使用聊天命令 `/米家登录` 完成同一登录流程。

### 步骤 3：同步云端设备

进入“设备管理”，点击 **同步云端设备**。页面会展示设备名称、在线状态、DID 和 model：

```text
1. 【未配置别名】(米家智能空气炸锅 5.5L 可视版) [🟢]
   DID: 1234567
   model: careli.fryer.maf07c

2. 【未配置别名】(主卧 体脂秤) [🟢]
   DID: 7654321
   model: yunmai.scales.ms103
```

其中：

- `【未配置别名】`：表示你还没在插件里给它取控制用别名
- 括号里的内容，例如 `米家智能空气炸锅 5.5L 可视版` / `主卧 体脂秤` / `卧室空调`：是米家云端当前显示名称
- `DID`：插件实际绑定设备使用的唯一标识
- `model`：设备型号，**用于设备画像适配、提交 Issue、排查兼容性问题**

聊天命令 `/刷新米家` 仍然保留，可作为同步设备和查看 DID、model 的备用方式。

### 步骤 4：可视化配置别名与类别

直接在设备列表中为需要使用的设备填写别名，并从下拉列表选择类别。建议别名使用“房间 + 设备”，例如：

```json
{
  "卧室净化器": "1234567",
  "客厅 空调": "8888888"
}
```

对应的设备类别用于提供中文状态、中文属性和更友好的帮助信息。例如：

```json
{
  "卧室净化器": "净化器类别",
  "客厅 空调": "空调类别",
  "空气炸锅": "空气炸锅类别",
  "扫地机": "扫地机类别",
  "厨房 热水壶": "热水器类别",
  "书房 路由器": "路由器类别"
}
```

底层配置说明：

* 类别映射的键（Key）必须与设备别名完全一致
* 类别值（Value）必须是页面下拉列表中的合法类别
* 无法识别的类别会按 `无类别` 处理

为什么这一步重要？

因为米家云端名称可能是用户自己改过的。配置设备类别后，插件就能赋予它：

* 中文化的可调属性
* 中文化的状态传感项
* 更友好的 `/米家帮助`
* 更稳定的 `/米家详情`

💡 特别说明（模型降级机制）：

本插件内置了型号精确匹配 机制。如果你设备的具体型号（Model，如 `yunmai.scales.ms103`）已经被开发者直接写进了核心字典库中，插件将无视你在这里配置的类别，直接采用最完美的型号专属配置。配置类别主要是为了给尚未收录专属型号的设备进行泛用性兜底。

### 步骤 5：检查并保存

点击 **检查并保存**，确认变更摘要后写入配置。页面保存的仍是原有 `device_map` 与 `device_category_map` 数据，旧版本的 JSON 映射会自动读取，**无需迁移或重新绑定**。

AstrBot 原生插件配置页中的 JSON 编辑项仍会保留，供高级用户和故障排查时使用。

### 步骤 6：查看只读状态

保存映射后，可在设备列表中打开设备详情，读取该设备的实时状态。这里仅提供只读查询，不会显示开关、属性设置或设备动作入口。

### 步骤 7：在聊天中使用

完成配置后，可以先测试：

> `/米家详情 卧室净化器`
>
> `/米家帮助 卧室净化器`

设备控制和场景执行仍然只通过聊天命令或已明确开启的 LLM Tool 进行：

> `/米家控制 卧室净化器 开`
>
> `/米家场景 晚安模式`

### 🏠 “米家管理”页面能做什么

内置页面定位为配置与诊断中心，提供：

- 米家账号扫码授权、登录状态查看和退出登录。
- 云端设备同步，以及设备别名、类别映射的可视化编辑。
- 已缓存场景查看、场景目录同步和 LLM Tool 权限配置。
- 已映射设备的只读实时状态。
- 登录、网络、共享设备、缓存和映射配置诊断。

WebUI **不提供设备控制按钮，也不提供场景执行按钮**。即使在页面中开启场景 Tool，场景也只能由聊天中的 LLM Tool 在权限规则允许时请求执行；建议始终开启“仅管理员可调用”。

### 🔄 旧配置兼容与高级入口

从旧版本升级时，原有 `device_map` 和 `device_category_map` JSON 映射会直接沿用，无需手动迁移。内置页面保存后仍使用相同的配置结构，因此可以与 AstrBot 原生插件配置页互相兼容。

原生配置页中的 JSON 编辑器会继续保留，适合批量编辑、备份或紧急修复。普通使用建议优先通过“米家管理”操作，以获得输入校验、变更摘要和类别选择提示。

### 🔐 数据存储边界

| 数据 | 存储位置 | WebUI 行为 |
| :--- | :--- | :--- |
| 米家登录凭证 | AstrBot 数据目录下的 `plugin_data/astrbot_plugin_mihome/auth.json` | 只显示“凭证是否存在”，不允许查看或下载 Cookie、Token 和文件内容 |
| 设备、场景与诊断状态 | 同目录下的 `state.json` | 仅展示脱敏后的缓存和最近运行状态 |
| 设备映射与 Tool 开关 | AstrBot 管理的本插件配置文件 | 通过白名单字段校验后保存，与原生插件配置页共用 |

扫码登录链接只在当前插件进程的内存中短暂保存，用于本地生成二维码；原始链接不会返回给 WebUI，登录成功、超时或退出后也会立即清除。

支持执行米家 APP 中已配置的“手动执行”场景。

### 📱 前置准备
1. 打开米家 APP，进入底部的 “智能” 页面。

5. 保存并起一个有辨识度的名字，例如：
   - `晚安模式`
   - `离家全关`
   - `关净化器`
   - `影院模式`
> 建议尽量避免过于模糊或重复的场景名，例如仅命名为 `晚安`、`离家`、`开灯`。  
> 更清晰的命名有助于指令匹配，也更利于大模型安全调用。

### 🎮 场景控制指令

#### `/米家场景列表`
同步并查看当前账号下所有可执行的云端场景。
功能说明：
- 插件会从米家云端拉取当前账号下的场景列表
- 成功后会将结果缓存到插件本地，供后续大模型只读 Tool 使用
- 输出内容通常包括：
  - 场景名称
  - `scene_id`
  - 家庭标识（若可获得）

示例：
`/米家场景列表`

#### `/米家场景 [场景名或scene_id]`
立即执行指定场景。

示例：
`/米家场景 晚安模式`  
`/米家场景 123456789`

#### ⚠️ 同名场景保护
如果你的米家账号下存在多个同名场景，插件为了避免误操作，不会直接执行，而是提示你：
- 改用唯一的 `scene_id`
- 或前往米家 APP 修改为更容易区分的名称

### 🛡️ 安全边界
大模型只允许使用场景能力，不会被开放以下高风险控制能力：
- 任意设备属性设置
- 任意设备动作调用
- `/米家控制` 底层透传
- 单设备直接开关、调温、改模式等高级控制
也就是说，大模型只能在你事先在米家 APP 中配置好的手动场景范围内工作。

### ⚙️ 如何启用
1. 打开 AstrBot WebUI 的插件配置页面  
2. 找到并开启：`enable_scene_tool`  
3. 保存配置并重载插件  
4. 在与机器人对话时正确触发大模型

### 🧠 大模型如何获取场景信息
大模型不会直接实时读取米家云端场景列表。  
它只能读取插件中最近一次同步成功后缓存下来的场景列表。
因此，如果你：
- 新增了场景
- 修改了场景名称
- 删除了旧场景

请先手动执行一次：
`/米家场景列表`
以刷新本地缓存，然后再让大模型使用场景 Tool。

---

### 📖 大模型可用的两个场景 Tool

#### 1. 只读 Tool：读取缓存场景列表
大模型可以读取插件中缓存的场景列表，以了解当前有哪些可执行场景。
适用场景：
- 用户明确提到“场景”
- 用户明确提出家居控制需求，但模型不确定应该执行哪个场景
- 模型需要先确认可用场景名称

#### 2. 执行 Tool：执行场景
大模型可以执行某个已缓存并可匹配到的场景。

### ✅ 建议触发场景 Tool 的自然语言
以下表达通常属于明确的家居控制意图，适合让大模型尝试匹配并执行场景：
- `执行晚安场景`
- `帮我关下灯`
- `帮我把净化器关了`
- `执行离家模式`
- `帮我切换到影院模式`

---

### ❌ 不建议直接触发场景 Tool 的表达
以下表达通常只是普通对话、问候或状态表达，不应直接触发家居场景：
- `晚安`
- `早安`
- `我要睡了`
- `我出门了`
- `回来了`
- `我要休息了`
这些话本身不等于明确授权执行家居操作。  
如果你希望机器人执行场景，请尽量说得更明确一些，例如：
- `执行晚安场景`
- `帮我关下家里的灯`
- `帮我把净化器关掉`

### 🛡️ 安全边界
本插件支持为大模型提供 **米家设备只读查看 Tool**，但该能力被严格限制为“只读”。

**大模型只允许：**
- 查看已配置别名设备的实时状态
- 读取温湿度、空气质量、电源状态、运行模式等只读信息

**大模型不允许：**
- 打开或关闭设备
- 修改任意设备属性
- 执行动作
- 透传 `/米家控制`
- 访问未配置别名的设备

也就是说，这个 Tool 只能“看”，不能“动”。

---

### ⚙️ 如何启用
1. 打开 AstrBot WebUI 的插件配置页面  
2. 找到并开启：`enable_readonly_tool`  
3. 保存配置并重载插件  

---

### 📌 重要规则：只能从别名中检索
大模型不能自由扫描你米家账号下的全部设备。  
它只能从你在 `device_map` 中**已经手动配置过的设备别名**里检索目标设备。

例如你配置了：
```json
{
  "卧室 温湿度计": "123456789",
  "卧室 净化器": "987654321",
  "客厅 空调": "888888888",
  "厨房 热水壶": "666666666",
  "书房 路由器": "777777777"
}
```

那么大模型只允许读取：
- 卧室 温湿度计
- 卧室 净化器
- 客厅 空调

而**不能**读取未配置别名的其他设备。

#### 📂 建议同时配置设备类别
为了让只读 Tool 更稳定地返回中文化状态，建议你在 `device_category_map` 中为相关设备配置类别，例如：

```json
{
  "卧室 温湿度计": "温湿度计类别",
  "卧室 净化器": "净化器类别",
  "客厅 空调": "空调类别",
  "厨房 热水壶": "热水器类别",
  "书房 路由器": "路由器类别"
}
```

**说明：**
- 如果设备型号已经命中插件内置的 `MODEL_PROFILES`，即使不手填类别，通常也能正常识别。
- 如果设备型号未命中内置模板，但你又想让大模型读取它，建议手动填写类别。

---

### 🧠 大模型可用的两个只读 Tool

**1. `list_configured_mihome_aliases`**
列出当前插件中已经配置好的米家设备别名。
*适用场景：*
- 模型不确定你有哪些设备别名。
- 用户说了“卧室那个温湿度计”“净化器”“空调”这类目标，但模型需要先确认精确别名。

**2. `read_mihome_device_status_by_alias`**
按精确别名实时读取设备当前状态。
*适用场景：*
- 用户明确要“看状态”。
- 用户询问温湿度、空气质量、电源状态、工作模式等信息。
- 模型已经确认了要读取的设备别名。

---

### ⏱️ 不使用缓存，默认实时读取
这个只读 Tool 不会使用状态缓存。每次调用时，都会尽量直接读取当前设备的实时状态。

这样做的目的是避免以下误解：
- 用户问的是“现在”的状态
- 机器人却返回几分钟前的旧数据

**因此：**
- 设备目录 / 别名映射可以缓存
- 设备实时状态默认不缓存

---

### ✅ 适合触发只读 Tool 的自然语言
以下表达通常适合触发米家设备只读 Tool：
- `帮我看看卧室的温湿度`
- `现在净化器开着吗`
- `帮我看下客厅空调现在什么模式`
- `看看现在空气质量怎么样`
- `卧室温度适不适合睡觉`

### ❌ 不适合触发只读 Tool 的情况
以下情况通常不应调用只读 Tool：
- 纯闲聊、寒暄
- 没有明确设备目标，也没有明确状态查询意图
- 想要直接控制设备的请求（这应属于控制或场景，而不是只读查看）

例如：
- `晚安`
- `我要睡了`
- `帮我开空调`
- `把净化器关了`

这些并不是“只读查看”请求。

**用户自然语言：**
> `@机器人 现在帮我看看卧室的温湿度，适不适合直接睡觉？`

**理想流程：**

<summary><b>🧠 技术细节：三层降级解析机制 (点击展开)</b></summary>

本插件采用以下顺序解析设备能力：

3. 原始能力探测：若为 `无类别`，返回原始英文属性菜单，支持英文指令透传。

<details>
<summary><b>💡 设备画像未完全适配？ (点击展开)</b></summary>

欢迎提交 Issue 帮助我们完善核心字典库（MODEL_PROFILES）。  
请附带 `/astrbot/data/plugin_data/astrbot_plugin_mihome` 下对应的 `.json` 文件，或在终端执行以下代码并提供输出：

```bash
python - <<'PY'
from mijiaAPI import get_device_info
import json
model = "你的设备model（注意：不是 /刷新米家 中显示的 DID）"
info = get_device_info(model)
print(json.dumps(info, ensure_ascii=False, indent=2))
PY
```

说明：
- `/刷新米家` 当前会同时展示设备 `DID` 与 `model`
- `device_map` 里填写的是 `DID`
- `get_device_info()` 这里填写的必须是 **model**，不是 DID
- 如果暂时拿不到 model，也可以先附上插件缓存目录下对应的 `.json` 文件协助排查

## ⚠️ 常见排障与常见问题

| 现象 | 可能原因与建议 |
| :--- | :--- |
| 插件详情页没有“米家管理” | 请确认 AstrBot 已升级至 `4.24.2` 或更高版本，并在升级后重载插件、刷新插件详情页。 |
| 管理页面无法连接或接口未匹配 | 先重载本插件再刷新页面；仍失败时请查看“诊断”和 AstrBot 控制台日志。 |
| 扫码登录一直等待或二维码过期 | 授权流程最长等待 120 秒；请等待旧流程结束后重新点击“扫码登录”。 |
| 设备找不到 / 共享异常 | 建议优先使用设备主账号扫码登录。 |
| 设备拒绝请求 | 可能修改了只读属性或值越界。请参考 `/米家帮助`。 |
| 详情页只有英文菜单 | 设备未内置且未配置类别。请检查 `device_category_map`。 |
| 提示实况获取失败 | 设备可能离线或处于深度休眠（如体脂秤未踩亮）。 |
| 网络异常 / 超时 | 可能发生 TLS 断连或被防火墙风控，建议稍后重试。 |
