# 🌟 AstrBot MiHome Control

基于 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 框架开发的米家智能家居云端控制插件，支持聊天指令、场景与 LLM Tool。

[![Moe Counter](https://count.getloli.com/get/@astrbot_plugin_mihome?theme=moebooru)](https://github.com/674537331/astrbot_plugin_mihome)

</div>

## ✨ 核心特性

* 🏠 **内置管理页**：在 AstrBot 插件详情页完成扫码登录、设备映射、场景同步、Tool 权限设置与运行诊断。
* 🔒 **扫码登录**：认证凭证保存在 `plugin_data` 目录；插件校验文件类型，并在支持 POSIX 权限的平台将目录与凭证限制为当前用户访问。Windows 需通过 AstrBot 运行账号与数据目录 ACL 限制访问。
* 🚀 **场景调用**：直接调用米家 APP 内已有场景，支持聊天指令和 LLM Tool。
* 🧠 **设备画像**：将用户别名、中文控制词与底层属性键解耦。
* 📊 **中文状态**：基于本地画像与云端结果，对设备状态进行中文翻译与单位美化。
* 🛡️ **白名单控制**：设备控制 LLM Tool 默认关闭，并使用 AstrBot 管理员权限、精确别名白名单与型号画像限定控制范围。

## 🛠️ 安装依赖

运行环境要求：

* AstrBot `>= 4.24.2`
* Python `>= 3.10, < 4.0`
* `mijiaAPI==4.1.3`
* `qrcode==8.2`

AstrBot 从插件市场安装或更新时会读取 `requirements.txt`。手动部署可在 AstrBot 使用的 Python 环境中执行：

```bash
python -m pip install -r requirements.txt
```

## 📖 使用指南

发送 `/米家帮助`（英文别名：`/mihome_help`）可随时查看完整指令总览；发送 `/米家帮助 [设备别名]` 可查看设备专属控制示例。

如果同时安装了 [astrbot_plugin_help](https://github.com/Kylerupinski/astrbot_plugin_help)，公开的 `/米家帮助` 会自动显示在 `/helps` 菜单中。该帮助插件默认隐藏管理员命令；如需在 `/helps` 中展开显示本插件的其他命令，请在其配置中开启 `show_all_cmds`。

<details>
<summary><b>🚀 快速上手：从零到控制你的第一台设备（点击展开）</b></summary>

对于初次使用的用户，请按照以下 5 步完成设备绑定与控制：

### 步骤 1：扫码授权登录

前往 AstrBot WebUI 的“插件”页面，打开“米家控制”详情中的“米家管理”，点击“开始扫码登录”，再使用米家 APP 扫码确认授权。

聊天命令 `/米家登录` 提供管理页引导，登录票据仅在内置管理页中处理。

### 步骤 2：同步设备

在“设备管理”中点击“同步云端设备”，或发送 `/刷新米家`。插件会读取账号下可见的设备，例如：

```text
1. 【未配置别名】(米家智能空气炸锅 5.5L 可视版) [🟢]
   DID: 1234567
   model: careli.fryer.maf07c

2. 【未配置别名】(主卧 体脂秤) [🟢]
   DID: 7654321
   model: yunmai.scales.ms103
```

其中：

- `【未配置别名】`：表示插件中尚未设置控制别名
- 括号内容：米家云端当前显示名称
- `DID`：设备 DID，用于 `device_map`
- `model`：设备型号，用于画像适配与兼容性排查

### 步骤 3：配置设备别名

推荐直接在“米家管理 → 设备管理”中填写别名并保存，例如“卧室净化器”“客厅 空调”。

AstrBot 原生“插件设置”中的 `device_map` 继续作为高级兼容入口：

```json
{
  "卧室净化器": "1234567",
  "客厅 空调": "8888888"
}
```

### 步骤 4：指定设备类别

在管理页的类别下拉菜单中选择设备类别。原生“插件设置”中的 `device_category_map` 也可以批量维护：

```json
{
  "卧室净化器": "净化器类别",
  "客厅 空调": "空调类别",
  "空气炸锅": "空气炸锅类别",
  "扫地机": "扫地机类别",
  "厨房 热水壶": "热水器类别",
  "书房 路由器": "路由器类别"
}
```

说明：

* 键（Key）必须与 `device_map` 中的别名完全一致
* 值（Value）必须是插件支持的合法类别
* 型号命中内置 `MODEL_PROFILES` 时，插件优先采用型号专属画像
* 类别画像用于中文展示、状态读取与管理员命令参考

### 步骤 5：开始测试

先查看详情与帮助：

> `/米家详情 卧室净化器`
> `/米家详情 扫地机`
> `/米家帮助 厨房 热水壶`

再发送控制指令：

> `/米家控制 卧室净化器 开`
> `/米家控制 扫地机 开始清扫`
> `/米家控制 扫地机 拖地水量 0挡`
> `/米家控制 厨房 热水壶 温度 85`

### 🔑 账号与管理

* `/米家登录`：显示安全引导，前往内置“米家管理”完成扫码授权。
* `/米家登出`：清除本地凭证与账号状态。
* `/米家状态`：查看插件登录状态、共享设备异常与最近一次控制记录。

### 📡 设备查询

* `/米家帮助`：查看完整指令总览，英文别名为 `/mihome_help`。
* `/刷新米家`：同步云端设备列表，输出带 **DID 与 model** 的设备总览，并刷新本地设备档案缓存。
* `/米家详情 [设备别名]`：查看设备能力与实时状态。
  * 优先级 1（型号精准匹配）：型号命中内置 `MODEL_PROFILES` 时使用专属属性与翻译。
  * 优先级 2（类别模板兜底）：未命中型号但配置了有效类别时，使用大类通用画像。

* `/米家帮助 [设备别名]`：查看设备常用控制方式、属性与推荐指令示例。

### 🎛️ 设备控制

基础电源控制：

* `/米家控制 [设备别名] [开/关]`
  * 示例：`/米家控制 落地扇 开`

高级属性控制：

* `/米家控制 [设备别名] [属性] [值]`
  * 示例：`/米家控制 空调 温度 26`
  * 示例：`/米家控制 扫地机 拖地水量 0挡`

动作触发控制：

* `/米家控制 [设备别名] [动作名]`
  * 示例（中文）：`/米家控制 扫地机 开始清扫`
  * 示例（英文）：`/米家控制 扫地机 start_sweep`
  * 示例（手误兼容）：`/米家控制 扫地机 start-sweep` 或 `start sweep`

> 💡 提示：
> 1. 推荐优先参考 `/米家帮助 [设备别名]` 返回的示例格式。
> 2. 休眠类设备（如体脂秤）建议在屏幕亮起时读取状态。
> 3. 新型号或不同固件可能存在能力差异，涉及多设备联动时优先使用米家 APP 中预先配置的手动场景。

<details>
<summary><b>🎬 米家智能场景支持（Scenes）（推荐的使用方式）（点击展开）</b></summary>

支持执行米家 APP 中已配置的“手动执行”场景。

### 📱 前置准备

1. 打开米家 APP，进入底部“智能”页面。
2. 点击右上角“+”创建新智能。
3. 触发条件选择“手动执行”。
4. 添加需要联动的设备操作。
5. 保存并使用清晰、有辨识度的名称，例如：
   - `晚安模式`
   - `离家全关`
   - `关净化器`
   - `影院模式`

> 建议避免过于模糊或重复的场景名。清晰命名有助于指令匹配和大模型安全调用。

### 🎮 场景控制指令

#### `/米家场景列表`

同步并查看当前账号下可执行的云端场景，结果会缓存到插件本地，供后续 LLM Tool 使用。

#### `/米家场景 [场景名或 scene_id]`

立即执行指定场景。

示例：

`/米家场景 晚安模式`
`/米家场景 123456789`

#### ⚠️ 同名场景保护

账号下存在多个同名场景时，插件会要求改用唯一的 `scene_id`，或先在米家 APP 中修改为更容易区分的名称。

</details>

<details>
<summary><b>🤖 大模型自然语言联动（场景 Tool）（点击展开）</b></summary>

### 🛡️ 权限边界

场景 Tool 使用米家 APP 中预先配置并同步到插件缓存的手动场景。

配置组：

```yaml
scene_tool:
  enable: false
  admin_only: true
```

推荐保留 `admin_only: true`。管理页与 AstrBot 原生“插件设置”共用同一份配置；任一入口保存后，另一入口刷新即可读取最新值。

### 🧠 大模型如何获取场景信息

大模型从插件最近一次同步成功的场景缓存中读取列表。新增、重命名或删除场景后，请执行 `/米家场景列表`，或在“米家管理”中点击“同步场景目录”。

### 📖 大模型可用的两个场景 Tool

1. `list_cached_mihome_scenes`：读取已同步的场景缓存。
2. `execute_mihome_scene`：执行明确匹配的场景。

### ✅ 建议表达

- `执行晚安场景`
- `帮我关下灯`
- `执行离家模式`
- `帮我切换到影院模式`

普通问候或状态表达不等于执行授权。需要运行场景时，建议明确说出“执行”与场景名称。

### 🔄 推荐使用习惯

1. 在米家 APP 中创建并命名手动场景。
2. 同步场景到插件缓存。
3. 通过 `/米家场景 [场景名或 scene_id]` 或明确的自然语言触发。
4. 根据 Tool 返回结果确认执行状态。

</details>

<details>
<summary><b>👀 米家设备只读查看（LLM Tool）（点击展开）</b></summary>

### 🛡️ 权限边界

只读 Tool 用于查看 `device_map` 中已配置别名设备的实时状态，例如温湿度、空气质量、电源状态和运行模式。

### ⚙️ 如何启用

在“米家管理 → 场景与 Tool”或 AstrBot 原生“插件设置”中开启 `enable_readonly_tool`。

### 📌 重要规则：从别名中检索

大模型从 `device_map` 的已配置别名中匹配目标设备：

```json
{
  "卧室 温湿度计": "123456789",
  "卧室 净化器": "987654321",
  "客厅 空调": "888888888"
}
```

### 🧠 大模型可用的两个只读 Tool

**1. `list_configured_mihome_aliases`**

列出插件中已配置的米家设备别名。

**2. `read_mihome_device_status_by_alias`**

按精确别名实时读取设备状态。

### ⏱️ 默认实时读取

状态查询每次调用均访问当前设备数据，设备目录与别名映射可使用本地缓存。

### 💬 交互示例

**用户自然语言：**

> `@机器人 现在帮我看看卧室的温湿度，适不适合直接睡觉？`

**理想流程：**

1. 大模型确认已配置别名。
2. 找到 `卧室 温湿度计`。
3. 调用只读 Tool 获取实时数据。
4. 结合读数给出自然语言解释。

</details>

<details>
<summary><b>🛡️ 米家设备控制（LLM Tool）（点击展开）</b></summary>

设备控制 Tool 默认关闭，提供四个工具：

* `list_mihome_devices`：列出白名单设备与静态能力概览。
* `inspect_mihome_device`：检查设备静态能力与云端观测能力。
* `control_mihome_device`：按顺序设置静态画像允许的属性。
* `call_mihome_action`：执行静态画像明确允许的动作。

推荐配置：

```yaml
control_tool:
  enable: false
  admin_only: true
  allowed_devices: []
```

使用规则：

* `admin_only` 仅采用 AstrBot 管理员判定，群主与群管理员身份不参与权限计算。
* `allowed_devices` 填写 `device_map` 中的精确别名，启用前至少选择一台设备。
* 直接控制要求设备命中可信的精确型号画像；动态能力仅用于检查。
* `control_mihome_device` 单批最多 5 项并按顺序执行，已完成项目保留结果。
* 同一插件实例同时执行一个设备控制任务，同一设备操作间隔至少 3 秒。
* 带参数动作只采用精确型号画像中验证过的参数结构。
* `unconfirmed` 表示网关已接收请求，但云端尚未确认真实设备执行结果；请继续读取实时状态确认。

建议先加入一台低风险设备，使用 `list_mihome_devices` 与 `inspect_mihome_device` 核对能力，再逐步扩大白名单。

</details>

<details>
<summary><b>🔄 从 v7 升级到 v8（点击展开）</b></summary>

v8 继续读取原有 `device_map`、`device_category_map`、`scene_tool` 与只读 Tool 配置。

升级后建议：

1. 将 AstrBot 升级到 `4.24.2` 或更高版本。
2. 确认依赖已更新到 `mijiaAPI==4.1.3`。
3. 打开“米家管理”，同步设备并检查别名、类别和场景缓存。
4. 新增的 `control_tool` 默认关闭；确需使用时，保留 `admin_only` 并逐项选择 `allowed_devices`。
5. `/米家登录` 从 v8 起提供管理页安全引导，重新授权请在内置页面扫码。

若管理页面未显示，请确认 AstrBot 版本并重载插件。手工维护 JSON 配置时，建议先备份再通过管理页保存。

</details>

<details>
<summary><b>🧠 技术细节：三层降级解析机制（点击展开）</b></summary>

本插件采用以下顺序解析设备能力：

1. 型号精准匹配：型号命中内置 `MODEL_PROFILES` 时使用专属画像。
2. 大类模板兜底：未命中型号但配置了类别时，使用通用中文模板。
3. 原始能力探测：`无类别` 设备返回云端原始能力，供状态展示和适配诊断。

动态探测是诊断信息；LLM 直接控制范围仅由精确型号画像和管理员白名单确定。

</details>

<details>
<summary><b>💡 设备画像未完全适配？（点击展开）</b></summary>

请仅提供：

* 设备 `model`

* 预期显示名称、可读属性或动作说明

提交前请删除 DID、Token、Cookie、账号、家庭、房间与认证文件内容。`auth.json`、`state.json` 和完整日志不得作为附件上传。

## ⚠️ 常见排障与常见问题

| 现象 | 可能原因与建议 |
| :--- | :--- |
| 看不到“米家管理” | 确认 AstrBot `>= 4.24.2`，更新后重载插件或重启 AstrBot。 |
| 设备找不到 / 共享异常 | 建议优先使用设备主账号扫码登录，并确认账号地区一致。 |
| 设备拒绝请求 | 可能修改了只读属性或值越界。请参考 `/米家帮助`。 |
| 详情页只有英文菜单 | 设备未内置且未配置类别。请检查 `device_category_map`。 |
| 提示实况获取失败 | 设备可能离线或处于深度休眠，例如体脂秤尚未唤醒。 |
| 网络异常 / 超时 | 可能发生 TLS 断连或云端风控，建议稍后重试。 |
| 启动时报 `_ARC4.pyd` 缺失 | 使用 AstrBot 实际运行的 Python 执行 `python -m pip install --force-reinstall --no-cache-dir pycryptodome==3.23.0`，再重启 AstrBot。 |
| 提示登录凭证文件无法读取 | 打开“米家管理”执行退出登录，确认本地凭证与账号缓存清理成功后重新扫码。 |
| 场景 Tool 设置未更新 | WebUI 与原生“插件设置”共用配置；保存后刷新另一个页面。 |
| LLM 控制范围为空 | 开启 `control_tool` 后，还需选择精确别名白名单并命中型号画像。 |
| 一批操作部分成功 | 操作按顺序执行，已完成项目保留结果；请逐项核对并重试失败项。 |
